# 赛博鱼乐项目剩余缺口审计

审计时间：2026-09-19（Asia/Shanghai）
审计范围：Android APP、Fastify/Prisma 服务端、React Web 管理端、Git 远端、线上服务与已连接真机。

## 结论

当前已完成签到 MVP、基础 APP、Web 管理端和线上接口闭环，但尚未达到完整生产交付标准。主要剩余风险集中在真实模型、APP 更新安全、媒体闭环、签到奖励/风控、部署同步和真实验收证据。

## 已实现

- APP 已有 CameraX、Room、DataStore、WorkManager、触发判定、声音/震动/通知、记录管理、用户中心和误报截图上传。
- LiteRT 代码已有契约校验、SHA-256、ECDSA 验签、原子切换和回滚实现。
- 签到已有 CheckInRecord、上海时区、每日幂等、概览、历史分页、日历月份切换和 Web 配置页。
- Web/Server typecheck/build 已纳入 `.github/workflows/android.yml`。
- 线上健康、签到概览、重复签到、历史和管理员签到配置接口已验证。
- 真机已验证签名 APP 安装、冷启动、监控页和最新镜头外控制布局。

## P0 / 发布阻塞

### 1. 真实模型与性能门禁未完成

状态：部分实现，未完成生产验收。

证据：`DetectorSlot` 默认仍为 `MockDetector`；仓库没有真实鱼漂模型训练报告、正式模型签名、FPS/P95/内存/发热报告，也没有野塘、竞技池、河湖三类误报/漏报门禁。

涉及：`app/app/src/main/java/com/cyberfish/app/inference/DetectorSlot.kt`、`LiteRtDetector.kt`、`ModelRepository.kt`、`项目规划文档/YOLO 模型训练规划书.md`。

### 2. APP 长期共享 Token 仍编入 APK

状态：未解决。

证据：`APP_API_TOKEN` 通过 BuildConfig 进入 release 构建；服务端仍按全局 APP Token 放行 APP 请求。需要设备注册、短期凭据、请求签名、重放保护和撤销机制。

涉及：`app/app/build.gradle.kts`、`app/app/src/main/java/com/cyberfish/app/network/ApiConfig.kt`、`cyberfish-admin/server/src/plugins/auth.ts`。

### 3. FORCE 更新仍未阻断主业务

状态：部分实现。

证据：APP 能解析 `updateType`，但设置页仍以“检查更新/打开网盘”为主，没有强制更新状态机、主业务阻断或完整自动安装链路；`AppUpdateInstaller` 只在安装动作被调用时生效。

涉及：`app/app/src/main/java/com/cyberfish/app/network/AppApiClient.kt`、`CyberFishApp.kt`、`SettingsScreen.kt`、`AppUpdateInstaller.kt`。

## P1 / 核心体验与运营

### 4. 误报视频闭环未实现

状态：部分实现。

当前只有截图缓存和上传；没有 CameraX VideoCapture、触发前后视频片段、回放、上传幂等键和完整 FileAsset URL 校验。

### 5. 实时监控数据和设置仍有占位

状态：部分实现。

位移/抖动/持续时间仍有静态文案；灵敏度滑块没有直接驱动监控使用的 TriggerConfig；相机旋转/cropRect 坐标映射未完整处理；推理后端和性能模式主要保存偏好，未证明影响真实 delegate/分辨率/帧率。

### 6. 模型 OTA 仍是“定期检查 + 手动安装”

状态：部分实现。

WorkManager 已有启动和 6 小时周期检查，但 `checkForUpdate()` 只标记待更新，不自动下载、校验和安装；真实网络中断、损坏模型、签名失败、加载失败和回滚的端到端证据缺失。

### 7. 模型下发与看板生命周期不完整

状态：部分实现。

模型目标设备匹配仍有 5000 台限制；Dashboard 推理 P95 仍最多读取 5000 条事件；没有完整 DailyMetric 聚合、事件/媒体保留清理和可靠 APK 下载量递增证据。

### 8. Web 运营详情闭环仍不完整

状态：部分实现。

版本/模型页面已有基础字段和详情能力，但发布前签名/哈希/兼容性门禁、完整详情审查和公开下载状态校验仍不完整。

## 签到专项剩余缺口

### 9. 奖励发放未实现

状态：未实现。

管理端可配置 rewards/cycleStrategy，但签到服务只写 `CheckInRecord`，没有 `CheckInRewardLog`、勋章/称号发放、幂等奖励记录和 APP 里程碑弹层/勋章墙。

### 10. 签到风控未实现

状态：未实现。

CHECKIN_RISK 配置已经存在，但签到接口没有 IP 频控、设备上限、同设备多账号检测、风控持久化和异常列表接口。

### 11. 签到规则校验不完整

状态：部分实现。

已校验时间格式、奖励天数/名称重复和里程碑数量；未校验每日结束时间晚于开始时间、活动结束时间晚于开始时间、奖励天数不超过周期上限、iconKey 预置白名单。

### 12. 签到错误语义和审计不完整

状态：部分实现。

关闭活动、窗口外和重复签到没有规划中的专用错误码语义；审计仍归入通用 `SITE_CONFIG`，没有独立 `CHECKIN_SETTINGS` 模块和完整 before/after 快照。REVIEWER 仍拥有 `siteConfig:publish`，超出规划中的 OPERATOR+ADMIN 发布/回滚矩阵。

### 13. APP 签到验收覆盖不足

状态：部分实现/未验证。

没有 CheckInScreen Compose/UI 自动化测试；没有离线签到缓存、配置 5 分钟刷新机制、历史列表独立月份筛选；Token 过期 session 非空时自动弹登录流程仍有风险。

## P2 / 隐私与工程质量

### 14. 隐私与本地数据管理不完整

缺少首次隐私同意、媒体上传说明、媒体空间上限、设备标识重置策略和完整数据生命周期证明。

### 15. 自动化与部署证据不完整

CI 已覆盖 Android 与 Web/Server 构建，但缺少服务端签到测试、迁移部署检查、部署后浏览器/API 冒烟和真机矩阵自动化。
